## 部署到百度云（180.76.54.211，Ubuntu 24.04）

**用户约束**：服务器上已有 FaceSeek（mengrengjiu.com，PM2 + node:3000 + nginx:80/443），
"不要破坏和改变原有的一切"。

**侦察发现**
- 2 核 / 3.3G 内存 / 79G 磁盘（用 6.7G）
- nginx 1.24 占 80/443，只有一个站点 faceseek（域名 mengrengjiu.com，TrustAsia 证书至 2027-02-17）
- PM2 + node 3000 跑 FaceSeek；/opt 下还有百度云 agent（bcm-agent/bsm-agent/heyeAgent）
- Python 3.12.3、Node 22、git 就绪
- **ufw active，只放行 22/80/443** → 8000 被拦；百度云安全组同样未放行 8000

**部署方案（零侵入）**
1. 代码打包传到 `/opt/investweb`（含 28M 数据库，保留全部数据）
2. `python3 -m venv` + 清华源装依赖
3. 新增 Basic Auth（`backend/app/core/auth.py`），`AUTH_PASSWORD` 为空则跳过（本地开发不受影响）
4. systemd 服务 `investweb.service`，监听 0.0.0.0:8000，开机自启
5. **nginx 新增独立 site**（server_name 精确匹配 IP → 反代 8000），没有修改 faceseek 的任何文件
6. `ufw allow 8000/tcp`

关键：因为安全组拦 8000，改用已开放的 80 端口 + nginx 按 IP 精确匹配转发。
域名请求仍走 faceseek 的 server 块，两者互不干扰。

**验证**
- 外网 `http://180.76.54.211/` 无认证 401、带认证 200
- `https://www.mengrengjiu.com/` 与 `/api/v1/health` 均 200（FaceSeek 未受影响）
- 15 个定时任务已启动；内存占用 142MB
- 时区 Asia/Shanghai 正确

**接线注意**：SSH 传密码用 OpenSSH 的 SSH_ASKPASS + SSH_ASKPASS_REQUIRE=force。
PowerShell 的 ConvertTo-SecureString 被安全策略禁止，paramiko 装不上（pip 源不可用）。
凭据脚本用完立即 rm。

**遗留风险**：当前 HTTP 明文，Basic 认证密码可被嗅探。
建议后续用 invest.mengrengjiu.com 子域名 + 独立证书上 HTTPS。

文档：`docs/DEPLOYMENT_BAIDU.md`（含回滚步骤）。

## 上线 HTTPS 二级域名（补充）

用户要求：公开给所有人看，不要登录；有二级域名可用。

**关闭认证**：`.env` 里 `AUTH_PASSWORD=` 留空，重启生效。公开前已核对暴露面：
持仓只有「示例组合（非个性化建议）」、trade_journal 0 条、system_settings 无密钥。认证代码保留。

**域名分流实测**（同一 IP、同一 80 端口，靠 Host 头区分）：
- Host=www.mengrengjiu.com → FaceSeek 接口 200 / InvestWeb 404
- Host=invest.mengrengjiu.com → FaceSeek 404 / InvestWeb 200
- Host=180.76.54.211 → InvestWeb 200

**证书的关键事实**：用户以为"域名有 SSL 就都有"，实际 FaceSeek 那张 TrustAsia 证书
SAN 只含 www.mengrengjiu.com 与裸域，**不含子域名**。用 invest 做 SNI 连 443，
返回的仍是 `CN=www.mengrengjiu.com` → 浏览器会报不匹配。

**解法**：certbot（apt 装 2.9.0）用 webroot 给 invest 单独签 Let's Encrypt：
```
certbot certonly --webroot -w /var/www/certbot -d invest.mengrengjiu.com \
  --non-interactive --agree-tos --register-unsafely-without-email
```
有效期至 2027-02-17，certbot.timer 自动续期（enabled+active），
续期后经 renewal-hooks/deploy/reload-nginx.sh 自动 reload。

**nginx 配置结构**（investweb 独立文件，仍不碰 faceseek）：
- 80 + server_name invest.mengrengjiu.com → 只留 acme-challenge 目录 + 301 到 https
- 80 + server_name 180.76.54.211 → 直接反代 8000（IP 无证书不能跳 https）
- 443 ssl → 反代 8000

**结果**：https://invest.mengrengjiu.com 200、证书校验通过；FaceSeek www/裸域仍 200。
线上页面已确认正常渲染，行情数据更新到 2026-11-19（定时任务在服务器上正常工作）。

**遗留**：完全公开后 `POST /api/refresh` 任何人可调（有并发锁，但可反复触发采集）。
若被滥用可对非 GET 请求加来源限制。

## 移动端适配（用户反馈手机不好看）

结论：**一套代码做响应式，不拆两套**。两套要维护两份，改一个功能改两遍。

改动（`frontend/src/styles/main.css` + `AppLayout.vue` + `RadarPage.vue`）：
1. ≤900px 侧栏改抽屉（汉堡按钮 + 遮罩，`navOpen` 状态，路由变化自动关闭）
2. **`.grid[style*="grid-template-columns"] { grid-template-columns: 1fr !important }`**
   —— 十几个页面把栏宽写在内联样式里（如 `minmax(300px,1fr)`），内联优先级高于类，
   媒体查询管不到，窄屏直接撑破视口。这是主要元凶。
3. `.grid > *, .split > * { min-width: 0 }`：grid 子项默认 min-width:auto，会被宽表格撑开
4. ≤640px KPI 改两列（原来单列要滚四屏才看到机会卡片）
5. 表格 `.table-wrap` 内部横向滚动
6. 顶栏 flex-wrap + 文本省略，避免"市场状态"撑破宽度

**踩的坑（重要）**：用 `chrome --headless --window-size=390` 截图时，
Windows 上最小窗口宽度约 485px，实际视口是 485，截图输出 390 宽 → 看着像"右侧被裁"，
差点误判成布局 bug。用注入诊断脚本量到 `vw=485, sw=485`（无溢出）才发现是工具假象。

正确做法：`scripts/screenshot-mobile.js`，走 CDP 的 Emulation.setDeviceMetricsOverride
模拟真机，并打印 `innerWidth/scrollWidth`。验证结果 `vw=390, sw=390` 零溢出。

线上已部署，截图：`docs/screenshots/mobile-before.png`（改前）、`mobile-390.png`、`mobile-radar2.png`。
