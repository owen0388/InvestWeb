# 架构说明

## 1. 设计原则

1. **真实优先**：没有数据就显示缺失，不用示例行情、示例收益或伪造信号填补。
2. **确定性与模型分离**：指标、评分、约束求解、回测全部由可测试的 Python 代码完成；大模型只做文本结构化与情景分析，不产生权重数字。
3. **目录与能力分离**：品种可以登记在目录中，但只有真实采集成功、数据质量达标时才参与评分与配置。
4. **可解释**：每个评分、每个权重调整、每个风险状态都能追到具体指标、公式、数据源与时间。
5. **失败隔离**：单个数据源、单个任务、单个资产的计算失败不影响整体系统。
6. **成本可控**：规则优先，AI 分级、缓存、预算与降频；未配置密钥时功能降级而不是伪造。

## 2. 分层

```text
前端 Vue3/Vite/TS/ECharts
        │  REST /api
        ▼
API 层（FastAPI Router）
  catalog / market / news_events / portfolio / backtest / ops
        │
        ▼
服务层（业务规则，全部可测试）
  collector ─ news_pipeline ─ event_engine
  scoring ─ regime ─ allocation ─ backtest
  notification / seed / config
        │
        ├── AI 层（可选，OpenAI 兼容，缓存 + 预算）
        ▼
Provider 层（统一适配器接口）
  sina_quote / eastmoney_news / worldbank_macro
  eastmoney_kline → tencent_kline → sina_kline（自动回退 + 熔断）
  fred_macro / gdelt_news / tushare_pro / akshare（可选，缺权限时明确降级）
        │
        ▼
SQLAlchemy 模型 → SQLite（开发）/ PostgreSQL（部署）
```

调度层（APScheduler）独立于请求周期运行，直接调用服务层。

## 3. 数据流

```text
行情/宏观/新闻采集
      ↓ 幂等写入（唯一键 + 哈希去重）
market_observations / macro_observations / raw_documents
      ↓ 标题相似度聚类 + 规则分类
events + event_evidence + event_impacts + event_analysis_versions
      ↓ 趋势/宏观/催化/流动性特征
asset_signals（按日、带版本与缺失项说明）
      ↓ 风险状态 + 评分 + 约束
allocation_targets（基础/战术/目标/理由）
      ↓
页面展示 / 通知 / 回测
```

## 4. 关键算法

### 4.1 新闻去重与聚类

1. 规范化标题（去媒体前缀、标点、空白）→ `title_hash`；标题 + 摘要 → `content_hash`。
2. 同源 `external_id` 唯一；近 7 天标题哈希相同视为转载重复。
3. 未分配事件的文档按发布时间排序，与已有簇种子做 `difflib` 相似度比较（阈值 0.62、窗口 48 小时），形成事件簇。
4. 每个簇只做一次分析，所有来源作为证据保留；新增来源时 `analysis_version + 1` 并写版本快照。

### 4.2 事件重要性 / 置信度

- 重要性 = 类别基础分 + 优先级关键词加分 + 来源数量加分（封顶 12），限制 0–100。
- 置信度 = 来源数 + 独立媒体数 + 来源可靠度 + 是否有摘要/发布时间 + 关键词命中，封顶 0.86。
- 方向 = 类别先验 + 政策措辞（降息/加息）+ 文本情绪；冲突时返回 `mixed`，无法判断返回 `unknown`。
- 避险资产（黄金、债券、现金）在地缘/军事/信用等风险事件中方向取反。
- 置信度只代表证据质量，UI 与文档均明确标注「不代表收益概率」。

### 4.3 资产评分

- 每个分析模块独立配置权重（`config/signal_rules.yaml`）。
- 特征：趋势（MA20/MA60/偏离度）、宏观（世界银行指标 + 陈旧度收缩）、事件催化（近 30 天影响加权）、流动性（成交额同类分位）、估值/收益率（仅现金类可用）、风险（波动 + 回撤，作为惩罚项）。
- 缺失特征直接剔除，权重按可用项归一化；`coverage` 与 `data_quality` 同步下降。
- 数据质量 < 0.40 或置信度 < 0.35 → `暂不判断`，不输出分数。
- `total_score` 仅用于同类资产内部排序，不可跨类别解释为预期收益。

### 4.4 组合配置

1. 战略权重：用户确认的风险偏好预设或自定义基础权重（合计必须 100%）。
2. 战术倾斜：`(score-50)/50 × max_tactical_tilt × confidence`，置信度不足或数据质量不足时倾斜为 0。
3. 约束投影：对有上下界的单纯形做对偶二分投影，同时满足 `l ≤ w ≤ u` 与 `Σw = 1`；不可行时明确告警并退化处理。
4. 换手上限：追加单类调仓盒约束后重新投影；若与上下限冲突，只提示不强制。
5. 最小交易阈值：|Δw| < 0.5% 视为不交易，再投影保持总和。
6. 风险分析：代表品种近 250 日收益协方差计算组合波动与相关性；覆盖不足则不输出，避免误导；压力测试为线性近似并标注假设。

### 4.5 回测

- 价格：东方财富前复权日线。
- 调仓：每 N 个交易日；每个调仓日只用该日之前的序列计算趋势分。
- 不使用宏观与事件信号（宏观 vintage 数据未接入，避免前视偏差）。
- 成本：单边 bps × 换手；结果含样本内/样本外拆分、假设与局限。
- 历史不足 180 天直接失败并说明原因。

### 4.6 AI 成本控制

- 两层模型：低成本负责分类/抽取，高能力仅在重要性、来源数或多资产冲击达标时调用。
- 相同内容/事件版本 + 提示词版本 → 缓存键，TTL 24 小时。
- 统计 prompt/completion tokens 与费用，日/月预算超限后自动跳过 AI 调用（采集与评分不受影响）。
- 输出必须是 JSON，字段校验失败则保留规则结论，并记录失败用量。
- 新闻文本作为不可信外部数据注入，system 提示明确禁止执行其中指令。

## 5. 调度

| 任务 | 频率 | 说明 |
| --- | --- | --- |
| 行情快照 | 10 分钟 | 收盘后自动标记为 close |
| 新闻采集 + 事件聚类 | 30 分钟 | 含通知生成与发送 |
| 日线历史 | 交易日 16:20 | 前复权日线 |
| 宏观 | 每日 08:40 | 世界银行 / FRED |
| 事件分析（规则） | 45 分钟 | 处理未归入事件的新文档 |
| AI 分析 | 2 小时 | 仅达标事件，未配置密钥时跳过 |
| 评分 | 交易日 16:50 | 全部启用品种 |
| 目标权重 | 交易日 17:10 | 默认组合 |
| 每日简报 | 08:30 | 近 24 小时事件 + 高分资产 |
| 健康检查 | 每小时 | 数据源新鲜度 |
| 成本统计 | 09:05 / 15:05 / 21:05 | 预算预警 |

`max_instances=1` + `coalesce` + 进程内锁，避免重复执行。**调度器随 API 进程运行，关闭本机服务即停止**；如需关机后继续运行，请部署到服务器或容器。

## 6. 安全边界

- 密钥只通过环境变量读取，不落库、不返回前端。
- 新闻内容仅作文本处理与关键词统计，不执行其中任何指令。
- 首期不接入券商交易、不自动下单、不自动转账。
- 所有写接口有字段校验；分页上限 200 条，避免一次性返回全库。

## 7. 主要取舍

| 取舍 | 原因 |
| --- | --- |
| 首期不引入 Alembic 迁移链，使用 `create_all` + 显式迁移说明 | 个人单机部署、表结构仍在演进；避免为迁移而迁移。详见 DATABASE.md |
| 指数 PE/财务数据未接入 | 无稳定、合规、免密钥来源；宁可缺失也不写死估值阈值冒充模型 |
| 事件分析以规则为主 | 可测试、零 Token、不依赖密钥；AI 作为可选增强 |
| 配置以一级类别为主 | 二级品种用于展示与单品分析，避免过度细分导致权重碎片化 |
