**三条会改变规则的发现**

1. **规模有两个口径，差得很远。** `f20`（份额×价格）与 `ENDNAV`（报告期净资产）在 159915 上分别是 1099 亿与 650 亿。准入用 `f20` 做实时门槛，`ENDNAV` 只做交叉校验，禁止混用。
2. **跨境 ETF 溢价可以很夸张。** 抽样中 513310 溢价 **+10.28%**，普通 ETF 在 ±0.2% 内。因此折溢价门禁不能全市场一个阈值：跨境单独放宽或单独标注，普通 ETF 用 ±3%。

### 1b 实测结果（2026-11-05）

**与计划的两处偏离（都是被迫的，且有依据）**

1. **跟踪误差做不了，换成「折溢价稳定性」。**
   跟踪误差 = std(ETF收益 − 指数收益)，需要指数序列，免费源拿不到成分/指数点位。
   用净值怼价格只会得到折溢价波动，**叫跟踪误差是错的**。因此改为折溢价绝对值中位数
   （近 60 个交易日、同日匹配、样本 ≥20 才算），含义明确且可复现。
2. **成交额仍是 1 日口径，没有升级成 20 日均额。**
   腾讯日线 `volume` 单位是「手」、新浪是「股」，相差 100 倍，用它反推成交额会得到数量级错误。
   在没有统一口径前，宁可标注 `amount_basis=1d`，也不用可能错 100 倍的估算值。

**质量分构成**

| 指标 | 权重 | 口径 | 可得性 |
| --- | --- | --- | --- |
| 流动性 | 40% | 当日成交额（f6），页面标注 `/1d` | 100% |
| 规模 | 30% | 市值口径 f20（不用报告期净资产，两者口径不同） | 100% |
| 折溢价稳定性 | 20% | 近 60 日 \|价格/净值−1\| 中位数，同日匹配 | 221/225 |
| 历史长度 | 10% | 日线根数（≥20 才计） | 225/225 |

- 横截面分位映射到 0–100，不用绝对值，避免市场整体水位变化导致分数漂移。
- 缺失项剔除后按剩余权重归一，置信度 = 可用权重占比（货币类 0.8，无折溢价）。
- 覆盖率 <50% 的指标整项停用，状态标 `disabled`。

**实测数据**

| 指标 | 值 |
| --- | --- |
| 候选池 | 223 只（盘中快照；收盘后为 254 只，差异见下） |
| 有质量分 | 223 / 223 |
| 新增日线 | 60,635 条（写入 `market_observations`，`instrument_id` 留空，不污染资产目录） |
| 质量分区间 | 2.34（巴西 ETF，规模小、流动性差）– 91.78（创业板 ETF 易方达） |
| 耗时 | 约 2.5 分钟（223 只 × 日线 + 净值，并发 4） |

**两个必须记住的坑**

1. **折溢价不能用「实时价 ÷ 净值」。**
   净值是 T-1，盘中价格是 T 日，直接相除会把当日涨跌算成溢价。实测 2026-11-05 盘中
   一次刷新，`premium>3%` 从 8 只暴增到 49 只、候选从 254 掉到 198。
   修法：先用涨跌幅还原前收盘价，再对净值，口径写入 `premium_basis`（实测 221 只用 prev_close）。
2. **盘中刷新拿到的成交额只有半日量。**
   门槛按全天量设定，盘中必然少一批。实测盘中 223 只 vs 收盘后 254 只。
   这不是数据错误，但必须显式提示：`/api/universe/summary` 返回 `session_state`
   （pre_open / intraday / after_close / closed）与 `session_note`，页面顶部用黄色条提示。

### 3-2 实测结果（2026-11-05）

**为什么先做这一步，而不是按手册先做事件映射**

1c 刚输出 6 条信号，但没有反馈闭环就无法判断信号有没有用。交易日志是唯一能区分
「策略错了」和「我没执行」的东西，优先级高于继续扩功能。

**表 `trade_journal` 的关键字段**

| 字段 | 作用 |
| --- | --- |
| `decision` | followed（照做）/ skipped（信号出现没做）/ manual（自己决定）——**没有这个字段，永远分不清是策略差还是没执行** |
| `signal_score` / `signal_state` | 下单当时的信号快照，事后不可改 |
| `invalidation` | 失效条件，**建仓时必填**（API 层 422 拦截），事后补等于没写 |
| `planned_price` vs `actual_price` | 滑点可算 |
| `pnl` / `pnl_pct` / `holding_days` | 平仓自动计算，含双边费用 |

**归因输出**（`GET /api/journal/stats`）

- 总体：胜率、平均盈利/亏损、盈亏比、期望收益、profit factor、平均持有天数
- 分组：按 `decision`、按资产类别
- `compare_followed_vs_skipped`：「照做」与「没做」的期望差，样本各 <5 时返回 None

**样本保护**：已平仓 <20 笔时 `reliable=false`，并输出警告「只作记录，不能据此判断策略有效」。
这是红线——3 笔盈利说明不了任何事。

### 3-1 / 2-x 实测补充（2026-11-05）

**发现的严重 bug：回测权重从不漂移**

原实现里权重只在调仓日更新，调仓日之间保持不变——等于**每天零成本自动再平衡**。
症状：「买入持有」和「定期再平衡」跑出完全相同的结果（都是 -0.19%，换手 0）。
修复后两者分离为 -0.39%（换手 0）与 -0.01%（换手 0.14），单策略回测也从 -1.53% 修正为 +0.34%。

**五策略对比（2025-09-24 ~ 2026-10-27，260 天，成本 8bps）**

| 策略 | 总收益 | 最大回撤 | 换手 |
| --- | --- | --- | --- |
| 买入持有 | -0.39% | -8.89% | 0.00 |
| 定期再平衡 | -0.01% | -8.93% | 0.14 |
| 评分倾斜 | +0.38% | -9.23% | 0.39 |
| 趋势跟随 | +1.48% | **-5.17%** | 3.44 |
| 相对强弱轮动 | **+12.45%** | -11.54% | 3.99 |
| 沪深300 | -11.31% | — | — |

**必须说明的限制**：样本仅 260 天（约 1 年），轮动的 +12% 高度依赖这一年的结构性行情，
不能据此认为轮动策略更好。分年数据显示 2025 年各策略差异极小（+2.9%~+3.2%），
差异主要来自 2026 年。

**事件映射的精度问题**

首版用「类别匹配 OR 主题匹配」，货币政策事件映射出 **144 只** ETF（等于把候选池列一遍）。
改为「必须主题命中 + 每族最多 2 只」后为 8 只（利率债/宽基/信用债/金融各 2）。

**顺带修的三个分类 bug**

## 4b. 数据刷新机制（2026-11-05 补齐）

**发现的两个洞**

雷达与质量分原本**没有任何定时任务**，只有手动接口：

| 层 | 原状态 | 后果 |
| --- | --- | --- |
| 行情快照 | 每 10 分钟 | 只覆盖资产目录 61 只 |
| 候选池 | 交易日 16:15 | 正常 |
| 候选池日线与质量分 | **无定时，仅手动** | 雷达用过期日线算分 |
| 雷达快照 | **无定时，仅 GET 时写** | 没人访问就断档，首次发现/环比失真 |

结果是**「假新鲜」**：页面上的分数是刚算的，底层日线可能是几天前的。这比数据过期更危险，因为看不出来。

**补齐后的任务队列（15 个）**

| 任务 | 周期 |
| --- | --- |
| 行情快照 | 每 10 分钟 |
| 新闻采集 / 事件分析 / AI 分析 | 30 / 45 / 120 分钟 |
| 数据健康检查 | 每小时 |
| 宏观 | 每日 08:40 |
| 候选池刷新 | 交易日 16:15 |
| **候选池日线与质量分** | **交易日 16:35（新增）** |
| **雷达快照** | **交易日 16:45（新增）** |
| 资产评分 / 目标权重 | 16:50 / 17:10 |
| 备份 / 简报 / 成本统计 | 02:30 / 08:30 / 9·15·21 点 |

**手动入口**

- `GET /api/refresh/status`：四层数据的最后更新时间、是否过期、是否有刷新在跑
- `POST /api/refresh {"scope": "quotes|universe|quality|radar|all"}`：后台执行，带全局互斥（409），单步失败不阻断后续
- 前端「机会雷达」页顶部新增刷新条：可见每层新鲜度 + 下拉选择作用域 + 轮询进度

**过期判定**：超过预期间隔 3 倍才算过期（与 health_check 一致），避免刚过 1 秒就报警。
