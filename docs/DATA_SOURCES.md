## 2. 数据类型标注规则

| 标注 | 判定 |
| --- | --- |
| 实时 `realtime` | A 股：当日且处于交易时段（9:30–11:30 / 13:00–15:00）且数据龄 ≤ 10 分钟；外盘/港股：数据龄 ≤ 15 分钟 |
| 延迟 `delayed` | 非交易时段但仍属当日，或外盘数据龄 15 分钟–24 小时 |
| 收盘 `close` | 已收盘的日线或非当日快照 |
| 人工 `manual` | `manual_entry` 来源或人工维护品种 |
| 缺失 `missing` | 从未成功采集 |

**不会把收盘价标注为实时，也不会给年度宏观数据标注实时。**

### 日线来源回退策略

```text
东方财富（仅沪深）→ 腾讯（沪深/港股/美股）→ 新浪（沪深，不复权）
外盘期货：新浪 GlobalFuturesService 日线
```

- 每次成功都会把**实际来源**写入 `market_observations.source_code`，页面与 API 均显示真实来源。
- 单次采集内某来源连续失败 2 次即熔断，避免整轮被拖慢。
- 数据源管理页的 `eastmoney_kline` 状态反映“日线任务”整体是否成功，消息中注明实际来源。

## 3. 宏观数据字段规范

- `period`：数据所属期间（如 `2025`）。
- `period_date`：期间结束日，用于陈旧度计算。
- `release_at`：实际发布时间；世界银行 API 未提供逐条发布时间，统一留空并在 UI 说明。
- `fetched_at`：系统采集时间。
- `revised`：是否被后续修订；首期世界银行/FRED 均按当前值入库，尚未实现 vintage 对比。

**禁止把 `period` 当 `release_at` 使用。** 评分中对年度数据按半衰期向中性收缩，并降低该特征 quality。

## 4. 未接入 / 无法接入的数据及原因

| 数据 | 原因 | 影响 | 替代方案 |
| --- | --- | --- | --- |
| A 股指数 PE/PB 历史分位 | 无稳定免密钥接口；商业接口需授权 | 评分缺「估值」特征，权益类 coverage 约 75% | 配置 Tushare/商业数据源后扩展 `provider` |
| 上市公司财报与盈利预期 | 需付费或授权；公告正文解析成本高 | 无基本面评分 | 巨潮公告采集（后续阶段） |
| 中国国债收益率曲线、信用利差 | 中债数据需授权 | 债券/黄金实际利率模型不完整 | 用国债 ETF 价格作为趋势代理，并在 UI 标注 |
| 基金净值、折溢价、跟踪误差 | 需基金公司/交易所接口 | 基金模块仅用二级市场行情 | 扩展 `FundDataProvider` |
| 银行理财、保险、房产估值 | 非公开、非标准化 | 标记为人工维护，不参与自动信号 | 用户手工录入 + 明确标注估值不确定 |
| 期权/期货实时行情 | 需期货公司或交易所授权 | 衍生品仅保留风险模型目录，权重上限 0 | 接入后启用 `derivative` 模块 |
| 新闻正文全文 | 版权与反爬限制 | 仅使用标题与摘要做规则分析 | 官方 RSS / 授权 API |

## 5. 频率与合规

- 新浪行情：单次批量 ≤ 40 个代码，间隔 0.4 秒；建议整体不超过 1 次/秒。
- 东方财富日线：间隔 0.25 秒；新闻：间隔 0.5 秒。
- 世界银行：每次刷新 15 个请求，串行。
- 所有请求带 User-Agent 与超时、重试、退避；失败写入 `data_source_runs` 与 `data_sources.last_error`。
- 不绕过登录、不破解签名、不抓取需授权页面。

## 6. 如何新增数据源

1. 在 `config/data_sources.yaml` 登记代码、类别、认证、频率、覆盖与说明。
2. 在 `backend/app/providers/` 实现适配器，返回统一的 `Quote` / `Bar` / `NewsItem` / `MacroPoint`。
3. 在 `providers/registry.py` 与 `collector_service.py` 注册采集函数。
4. 若需要密钥，加入 `Settings` 与 `.env.example`，未配置时 `available()` 返回 `False` 并给出原因。
5. 重启后端，在「数据源管理」页手动触发一次，确认状态与数据时间。
